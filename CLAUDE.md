# CLAUDE.md – Dealership (Spring Boot + Angular)

Car dealership app. Backend: Spring Boot 3.5, Java 21, JPA, H2 in-memory, Flyway. Frontend: Angular 22 (standalone, signals, signal forms), Vitest.
The **vehicle module is the reference implementation** – every new feature must look like it
(`backend/src/main/java/com/example/dealership/vehicle/`, `frontend/src/app/vehicles/`).

Requirements: `INTENT.md` (requirements, assumptions Z1–Z20, open questions). Decision log: `DECISIONS.md`.
Generating a new CRUD slice: use the `feature-slice` skill (`.claude/skills/feature-slice/`).

## Commands (JDK and Node exist only in the `salon-dev` container)

```bash
docker compose -f docker-compose.dev.yml up -d                       # start container if `docker ps` lacks salon-dev
docker exec salon-dev bash -lc 'cd /workspace && ./test.sh'           # ALL tests – must pass before every commit
docker exec salon-dev bash -lc 'cd /workspace/backend && ./mvnw -q test'
docker exec salon-dev bash -lc 'cd /workspace/backend && ./mvnw -q test -Dtest=CustomerServiceTest'
docker exec salon-dev bash -lc 'cd /workspace/frontend && npm test'
docker exec -d salon-dev bash -lc 'cd /workspace/backend && ./mvnw -q spring-boot:run'                 # API :8080
docker exec -d salon-dev bash -lc 'cd /workspace/frontend && node_modules/.bin/ng serve --host 0.0.0.0' # UI  :4200
```
The repo is mounted at `/workspace`. H2 is recreated and re-seeded on every start.

## Hard rules

- **Never edit an existing Flyway migration.** Add `V<max+1>__<snake_description>.sql`. Seed data goes in its own migration.
- **API contract in `BRIEF.md` is fixed**: paths, field names, enum values, 409 cases, readiness JSON shape. Do not rename or reshape.
- `spring.jpa.hibernate.ddl-auto=validate` → entity columns/types/lengths must match the migration exactly.
- No new dependencies (Maven or npm), no Lombok, no MapStruct, no custom CSS files.
- All user-facing text, validation messages, identifiers and commit messages in **English**.
- Do not touch the `error` package contract (`ProblemDetail` + `errors: [{field, message}]`) – reuse it.

## Backend conventions (package `com.example.dealership.<feature>`)

One package per feature with exactly these classes (see `vehicle/`):

| Class | Rule |
| --- | --- |
| `X` entity | `@Entity @Table(name = "x")` (snake_case singular), `@Id @GeneratedValue(IDENTITY) Long id`, `@Column(nullable, length)` mirrors SQL, `protected X() {}` + public constructor with all fields except id, getters + setters (no setter for id). Enums: `@Enumerated(EnumType.STRING) @Column(length = 20)`. |
| `XRepository` | `extends JpaRepository<X, Long>`; uniqueness via `existsByField` + `existsByFieldAndIdNot`. |
| `XRequest` | `record` with Bean Validation on components; `@NotBlank` + `@Size(max)` for strings, `@NotNull` for non-strings, custom message only when the default is unclear (lowercase, e.g. `"must be 17 characters: …"`). |
| `XResponse` | `record` with `id` first, then fields in entity order. |
| `XMapper` | `final class`, private ctor, static `toEntity(Request)`, `updateEntity(X, Request)`, `toResponse(X)`. |
| `XService` | `@Service @Transactional(readOnly = true)` on class, `@Transactional` on writes. `findAll()` uses `Sort.by("id")`. Missing → `NotFoundException("X with id N not found")`. Duplicate → `ConflictException("X with <FIELD> v already exists")`, checked **before** save; update loads the entity first (404 beats 409). |
| `XController` | `@RestController @RequestMapping("/api/<plural-kebab>")`, constructor injection, `@Valid @RequestBody`, POST → `201` + `Location` via `ServletUriComponentsBuilder.fromCurrentRequest().path("/{id}")`, PUT → 200 body, DELETE → `204`. |

- Cross-field / custom rules: annotation + `ConstraintValidator` (pattern: `ProductionYear` + `ProductionYearValidator`), validator returns `true` for `null` (leave null to `@NotNull`).
- Business rules that need state (time, other rows) belong in the service; throw `ConflictException` (409) or a validation-style 400.
- "Today" must come from the injected `java.time.Clock` bean (`config/ClockConfig`), never `LocalDate.now()` without a clock in new code.
- Service-level 400s (rules needing the clock or stored data): throw `RequestValidationException(List<ValidationError>)` – rendered exactly like Bean Validation errors.
- Document status rules live only in `DocumentStatus.canTransitionTo`; readiness rules only in `HandoverReadinessCalculator` (pure, unit-tested).
- DB: `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`, `CONSTRAINT uq_<table>_<col> UNIQUE (...)`, FK `fk_<table>_<ref>`.

## Backend tests (JUnit 5, AssertJ, Mockito) – mirror the vehicle tests

- `XServiceTest`: `@ExtendWith(MockitoExtension.class)`, `@Mock` repository, `@InjectMocks` service. Cover: list mapped & sorted, 404 on find/update/delete, create, 409 on create (verify `never().save`), update, 409 on update, delete.
- `XControllerTest`: `@WebMvcTest(XController.class)`, `@MockitoBean` service, `jsonPath`. Cover: list, get, 404 ProblemDetail, 201 + exact `Location`, 400 with sorted `errors[]` (`verifyNoInteractions`), bad enum → `"must be one of: …"`, 409, PUT 200/404/400/409, DELETE 204/404.
- `XRepositoryTest`: `@DataJpaTest`, save + flush + clear + read back all fields, every custom query (`exists…`) true/false cases.

## Frontend conventions (`frontend/src/app/<plural>/`)

- Files **without** Angular suffixes: `x-api.ts`, `x-list.ts/.html`, `x-detail.ts/.html`, `x-form.ts/.html`, `x-form.spec.ts`, `<plural>.routes.ts`. Classes `XApi`, `XList`, `XDetail`, `XForm`.
- `x-api.ts`: TS interface `X` (nullable backend fields as `T | null`), `type XRequest = Omit<X, 'id'>`, enum as string-union + `X_LABELS: Record<Enum, string>` + `XS = Object.keys(...)`. `@Injectable({ providedIn: 'root' })`; reads via `httpResource` (`list()` with `defaultValue: []`, `get(id: Signal<number | undefined>)`); writes via `HttpClient` returning `Observable`.
- Form: signal forms (`form`, `required`, `FormField`, `FormRoot` from `@angular/forms/signals`), model via `linkedSignal` + `toFormModel`/`toRequest`, `submission.action` with `firstValueFrom`, errors via `problemDetailToFormErrors`. **Frontend validates only `required`** (message `"<Label> is required"`); formats/ranges come from backend 400. Optional empty strings are sent as `null`.
- List/detail: `isLoading` / `error` (`loadErrorMessage(err, 'X not found')`) / `value` states, `@empty` row, delete with `deleteError` signal + `reload()`.
- Routing: `''`, `'new'`, `':id/edit'`, `':id'`; lazy `loadChildren` in `app.routes.ts`; nav link in `app.html` with `routerLinkActive="active"`. Route params as `input` (`numberAttribute` / `optionalNumberAttribute`).
- Tests: Vitest + `TestBed`, `provideHttpClient()`, `provideHttpClientTesting()`, `HttpTestingController` (`expectOne`, `flush`, `afterEach(http.verify)`), `vi.waitFor`. Pattern: `vehicle-form.spec.ts`.

## Definition of done

1. Compiles; `./test.sh` green in the container (starter tests included – a red starter test is a regression).
2. Every business rule has a test; every 400/404/409 path has a controller test.
3. API matches `BRIEF.md` character by character.
4. Small commit per logical step (imperative English subject), `ai-logs/` included. Never `git push` without explicit user consent.
5. Any AI mistake or manual fix recorded in `DECISIONS.md`.
